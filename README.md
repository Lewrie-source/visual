# Сервер синхронизации субтитров

Крошечный сервер без зависимостей (только стандартная библиотека Python 3.8+).
Хранит в памяти «комнаты»: что играет у хоста и на какой секунде. Музыку и тексты не передаёт —
зрители сами берут текст с lrclib.

Через сервер проходит только: название, исполнитель, альбом, длительность, позиция и пауза/плей.

## Запуск локально (проверка)

    python server.py            # порт 8080, либо переменная PORT

Адрес в настройках приложения: `http://localhost:8080`

## Бесплатный деплой на Render

1. Создай репозиторий на GitHub и положи в него `server.py` и `requirements.txt` (и `render.yaml`).
2. На render.com: **New → Web Service** → выбери репозиторий.
3. Runtime: **Python**, Plan: **Free**.
4. Build Command: `pip install -r requirements.txt`
5. Start Command: `python server.py`
6. Advanced → Health Check Path: `/health`
7. После деплоя получишь адрес вида `https://имя.onrender.com` — его вписывают хост и зрители
   в поле «Адрес сервера».

Файл `render.yaml` — готовая заготовка для варианта «Blueprint»; если он не подошёл, используй ручные шаги выше.

### Что нужно знать про бесплатный план

- Сервис засыпает после ~15 минут без запросов; первое подключение после сна занимает около минуты
  (в настройках будет «будим сервер»). Чтобы не засыпал, можно настроить бесплатный пинг
  (например, UptimeRobot) на `https://имя.onrender.com/health` раз в 5–10 минут.
- Бесплатных часов в месяц хватает на работу 24/7 для одного сервиса. Условия Render меняются —
  проверь актуальные на их сайте.
- Состояние хранится в памяти: после перезапуска комнаты пропадают, хост пересоздаёт их сам.
- Лимиты: 100 комнат, 40 зрителей на комнату. Для компании на ~10 человек трафик ничтожен.
- Это любительский сервер, не для продакшена. Код комнаты работает как пароль — придумай длинный
  (кнопка «Новый» делает 8 символов).
